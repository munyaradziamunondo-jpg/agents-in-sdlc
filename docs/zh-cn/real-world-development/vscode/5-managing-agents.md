Copilot 处于代理模式时，会自主探索代码库、提出更改、编辑文件并运行命令。由于工作会实时发生在你的计算机上，VS Code 中的 Copilot Chat 会显示每次工具调用和文件编辑。你可以直接检查差异、接受或拒绝单项更改，并通过后续提示引导对话，无需离开编辑器。

本练习中，你将：

- 实时监控无障碍代理的工作。
- 审查并接受建议的文件编辑。
- 在会话进行中引导代理添加浅色模式切换开关。

## 场景

[练习 4][previous-lesson]中的无障碍自定义代理正在实现高对比度模式。工作进行中，设计团队提出了额外需求：为觉得默认主题太暗的用户添加浅色模式切换开关。无需从头开始新会话，你将引导现有会话扩展工作范围。

## 监控 Copilot 进度

Copilot Chat 视图会显示代理执行的每个步骤，包括探索的文件、运行的命令和提出的编辑。每项文件编辑都会在聊天中以差异形式显示，并提供 **Keep** 和 **Undo** 控件。

1. 返回练习 4 使用的 Copilot Chat 视图。
2. 代理工作时滚动聊天内容，查看工具调用、文件读取、文件编辑和终端命令。
3. 代理提出文件编辑时，差异会内嵌显示：
   - 选择 **Keep** 接受更改。
   - 选择 **Undo** 撤销更改，让代理再次尝试。
4. 也可打开聊天顶部的 **Files changed** 指示器，查看代理在此会话中修改的完整文件列表。

> [!NOTE]
> 如果工具调用请求权限（例如运行终端命令），代理会暂停并显示 **Allow** 提示。只批准你认可的命令。

5. 等待代理完成高对比度模式。它会发送总结所做更改的最终消息。

## 引导代理添加浅色模式

高对比度模式完成后，在同一对话中添加浅色模式切换开关。继续使用同一聊天会话，代理便会保留先前工作中的上下文，包括修改的组件、样式方法和本地存储模式。

1. 在 Copilot Chat 输入框中发送以下后续提示：

   ```plaintext
   做得不错！现在在高对比度切换开关旁添加浅色模式切换开关。浅色模式应遵循相同模式：通过本地存储保留设置，并且可从 UI 的同一区域访问。用户应能分别启用高对比度模式和浅色模式。
   ```

2. 代理会检查已做的更改，并提出浅色模式相关修改。
3. 按照高对比度模式的方式逐项审查编辑，使用 **Keep** 或 **Undo**。
4. 如果代理的实现方向不符合预期（例如尝试重构切换用户界面（UI）），可以选择聊天输入框旁的 **Stop** 按钮停止，再发送说明性后续消息。

> [!TIP]
> 引导进行中的会话比重新开始更快。可以要求调整（“简化 CSS，使用 CSS 变量而不是重复选择器”）、纠正方向（“不要添加第三个切换开关，将浅色模式整合到现有用户界面（UI）设置面板”）或扩展范围（“为两个切换开关添加键盘快捷键”）。

## 审查工作集

提交工作前，快速检查代理修改的所有内容。

1. 在 VS Code 中打开 **Source Control** 视图。
2. 查看所有更改文件。应能看到 Astro 组件、样式和相关测试的更新。
3. 打开部分已更改文件并检查差异。确认自定义代理规定的无障碍模式已体现，例如无障碍富互联网应用（ARIA）属性、键盘导航、语义化 HTML 和本地存储持久化。
4. 确认满意后，在 Source Control 面板中暂存并提交更改。下一课会发布这些更改。

## 总结和后续步骤

你使用 Copilot Chat 代理模式监控并引导进行中的会话，逐项审查文件编辑、接受或拒绝更改，并通过后续提示扩展任务，同时保留上下文。

本课中，你：

- 实时监控代理的工作。
- 接受或拒绝单项文件编辑。
- 使用后续提示引导正在进行的会话。
