アプリケーションの最も簡単な更新でも、通常は複数のファイルを変更し、テストを実行するなどの作業が必要です。開発者は、関連ファイルを探し、変更を加え、テストを実行してデバッグし、更新し忘れたファイルを見つけて、さらに変更を加えます。作業は際限なく続くように感じられます。

Copilot Agent Mode は、こうした作業に役立ちます。

Copilot Agent Mode は統合開発環境 (IDE) 内で、より自律的に作業できるように設計されています。開発者と同様に、既存のプロジェクト構造を調べ、必要な変更を行い、テストなどのタスクを実行し、見つかった問題を自動的に修正します。Agent Mode を使って、サイトに新しい機能を追加する方法を確認しましょう。

> [!NOTE]
> 名前は似ていますが、エージェントモードと cloud agent は異なる利用方法を想定しています。エージェントモードは IDE 内で作業し、すばやいフィードバックと対話を可能にします。cloud agent はチームメンバーのように非同期で作業し、課題やプルリクエストを通じて開発者とやりとりします。

この演習では、次のことを学びます。

- Copilot Agent Mode がプロジェクトを調べ、関連ファイルを見つけ、複数のファイルを連携して変更する方法。
- GitHub Copilot Agent Mode が UI とデータレイヤーにまたがる新機能を実装する方法。
- コードベースにマージする前に、Copilot Agent Mode が生成した変更とテストをレビューする方法。

## シナリオ

ゲームの一覧が増えてきたため、カテゴリとパブリッシャーで絞り込めるようにします。前の演習ではパブリッシャーヘルパーを追加しました。ここでは、Copilot Agent Mode を使って残りのデータレイヤー、ユーザーインターフェイス (UI)、テストを実装します。

## Tailspin Toys の Web サイトを実行する

変更を加える前に、Tailspin Toys の Web サイトを確認し、現在の機能を把握します。

この Web サイトは、開発者をテーマにしたボードゲームのクラウドファンディングプラットフォームです。ゲームの一覧と詳細を表示できます。単一の Astro アプリであり、ビルド時にページを HyperText Markup Language (HTML) の静的ファイルとして生成します。ページは frontmatter から Drizzle のオブジェクト関係マッピング (ORM) を通じてローカルの SQLite データベースに直接クエリします。別のバックエンドのアプリケーション プログラミング インターフェイス (API) やクライアント側のユーザーインターフェイス (UI) フレームワークはありません。再利用可能なデータアクセスヘルパーは `src/lib/` に配置し、対話機能は標準の Document Object Model (DOM) API を使う小規模で限定的な Astro `<script>` で追加します。

### Web サイトを起動する

Web サイトを簡単に実行できるよう、単一 Astro 開発サーバーを起動する `npm run dev` タスクが用意されています。GitHub Codespace で次の手順を実行します。

1. Codespace に戻ります。前の演習の後で `main` に戻っているはずです。
2. Codespace 内で <kbd>Control</kbd>+<kbd>`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>`</kbd> (Windows/Linux) を押して、新しいターミナルを開きます。
3. フィルタリング作業用のブランチを作成し、切り替えます。

   ```bash
   git checkout main
   git pull
   git checkout -b filtering-vscode
   ```

4. 次のコマンドを実行して Web サイトを起動します。

   ```bash
   npm run dev
   ```

   Astro 開発サーバーの準備ができると、次のような URL を示すメッセージが表示されます。

   ```bash
   🚀 Tailspin Toys is ready!
      Astro server: http://localhost:4321
      Press Ctrl-C to stop.
   ```

> [!NOTE]
> `http://localhost:4321` を開くよう促すダイアログが表示された場合は、**x** を選択して閉じます。

5. ターミナルに表示された Astro サーバーのアドレス `http://localhost:4321` を、Mac では <kbd>Command</kbd>、Windows/Linux では <kbd>Ctrl</kbd> を押しながら選択して Web サイトを開きます。

> [!NOTE]
> Codespace のターミナルで localhost の URL を選択すると、自動的に `https://<your-codespace-name>-4321.app.github.dev/` に転送されます。これは、Web サーバーをホストする Codespace へのプライベートトンネルです。

### Web サイトを確認する

Web サイトが起動したら、機能を確認します。主な機能は次のとおりです。

- **ホームページ**: ボードゲームのタイトル、画像、説明を一覧表示します。
- **ゲーム詳細ページ**: ゲームを選択すると、タイトル、説明、パブリッシャー、カテゴリなどの詳細ページが表示されます。

## Copilot でバックログを確認する

> [!TIP]
> **Copilot Chat を開く**
>
> 次の演習を始める前に Codespace に戻り、Copilot Chat パネルを開き、**New Chat** を選択して新しい会話を始めます。モードとモデルの選択は演習によって異なります。必要な場合は、各手順で説明します。

Web サイトの初期実装は動作しますが、新しい機能を追加したいと考えています。まず、バックログを確認します。テンプレートからプロジェクトを作成すると、課題のバックログも自動的に作成されています。GitHub Copilot に内容を表示するよう依頼します。

1. Chat ビューのエージェント一覧から **Agent** を選択します。**Agent** は自律的に計画を立て、複数のファイルにわたって変更し、ターミナルコマンドを実行し、ツールを呼び出します。

   ![Chat ビューでエージェントを選択する画面](../../../_images/shared-chat-mode-selector.png)

2. 使用可能なモデル一覧から **Claude Sonnet 4.5** を選択します。

> [!CAUTION]
> このワークショップの作成者が、特定のモデルを推奨しているわけではありません。ワークショップの作成時に Claude Sonnet 4.5 を使ったため、手順にも記載しています。提案の一貫性を高め、円滑に進めるためのものです。ただし、大規模言語モデル (LLM) の出力は確率的であるため、ここに記載したものとは異なる提案が表示されることがあります。これは想定どおりの動作です。

> [!NOTE]
> LLM の確率的な性質により、Copilot が別の MCP コマンドを使う場合がありますが、タスクは完了できるはずです。

3. 次のプロンプトを Copilot に送信して、課題のバックログを確認します。

   ```plaintext
   GitHub リポジトリのバックログにある課題を表示してください。ユーザーに最も役立つものを基準に、優先順位を付けてください。
   ```

4. **Continue** を選択して、すべての課題を一覧表示するコマンドを実行します。
5. 生成された課題一覧を確認します。

Copilot がユーザーにとって役立つかどうかを基準に、課題の優先順位も付けたことを確認してください。

## 指示ファイルを確認する

Copilot にコードを生成させる前に、作業のコンテキストを提供する指示ファイルを確認します。Web サイトへの機能追加方法に関するコンテキストを含む[ユーザーインターフェイス (UI) 指示ファイル](https://github.com/github-samples/tailspin-toys/blob/main/.github/instructions/ui.instructions.md)を使います。

1. Codespace で `.github/instructions/ui.instructions.md` に移動します。
2. 機能追加の進め方に関する全体的なガイダンスを確認します。次の内容が含まれます。
   - アーキテクチャの概要。
   - コンポーネントの設計、テスト容易性、アクセシビリティに関する原則。
   - Astro、Tailwind CSS、Drizzle などのファイル形式に関する指示ファイルへのリンク。

> [!TIP]
> 指示ファイルから、ほかの指示ファイルやプロジェクト内のファイルを参照できます。パスは指示ファイルからの相対パスです。指示を再利用し、大きな内容を小さなファイルに分け、Copilot に例やテンプレートを示すことができます。

## フィルタリング機能を実装する

フィルタリングを完成させるには、少なくとも次の 3 つを変更する必要があります。

- データレイヤー (`src/lib/`) に残りのフィルタリングロジックを追加または調整する。
- フィルタリング動作を確認するテストを追加または更新する。
- ゲーム一覧ページにフィルタリング UI を追加する。

また、コードベースにマージする前にテストを実行し、成功する必要があります。Copilot Agent Mode にこれらの作業を依頼します。

1. 現在の Copilot の会話を続けるか、**New Chat** を選択して新しい会話を開始します。
2. **Add Context**、**Instructions**、**ui** の順に選択し、指示ファイルを追加します。

   ![UI 指示ファイルを選択する画面](../../../_images/ex3-select-instructions-file.png)

3. Chat ビューのエージェント一覧で **Agent** が選択されていることを確認します。

   ![Chat ビューでエージェントを選択する画面](../../../_images/shared-chat-mode-selector.png)

4. モデルが **Claude Sonnet 4.5** のまま選択されていることを確認します。
5. 次のプロンプトを使い、バックログの関連課題に基づいて機能を実装するよう Copilot に依頼します。

   ```plaintext
   関連する GitHub のバックログ課題の要件に基づいて、サイトにパブリッシャーとカテゴリによるフィルタリングを追加してください。前の演習で追加したパブリッシャーヘルパーは維持し、必要に応じて調整しながら、残りのデータレイヤー、UI、テストを完成させてください。完了前に、すべてのテストが成功することを確認してください。サーバーはすでに起動しているため、起動する必要はありません。
   ```

6. Copilot がプロジェクトを調べ、目的の機能に関係するファイルを探す様子を確認します。データレイヤーのヘルパー、UI、テストを見つけてから、ファイルを変更してテストを実行します。

   ![Copilot がプロジェクトのファイルを調べる画面](../../../_images/ex3-agent-mode-explores.png)

> [!NOTE]
> Copilot はプロジェクトの調査、ファイルの変更、テストの実行など、複数の作業を行います。タスクとコードベースの複雑さによって、数分かかることがあります。処理中、コードエディターに **Keep** と **Undo** が表示される場合があります。Copilot の作業が完了すると、変更ごとに **Keep** または **Undo** を選べるようになるため、作業中に選択する必要はありません。

7. Copilot に求められたら、**Continue** を選択してテストを実行します。

   ![Copilot Chat にテストを実行してよいか確認するダイアログ](../../../_images/ex3-agent-mode-run-tests.png)

8. 作業中に処理が一時停止したり、テストが失敗したりすることがあります。問題ありません。Copilot はコード生成とテストを繰り返し、エラーがないと判断するまで作業を続けます。

   ![Copilot Agent Mode のセッションが完了した画面](../../../_images/ex3-agent-mode-proposed-changes.png)

9. 生成されたコードに問題がないか確認します。

> [!CAUTION]
> Copilot などの AI ツールが生成したコードは、必ずレビューしてください。

10. Web サイトが起動しているブラウザーに戻り、新しい機能を試します。
11. 動作とコードを確認したら、Copilot Chat ウィンドウで **Keep** を選択します。

## まとめと次のステップ

GitHub Copilot Agent Mode を使って、Tailspin Toys の Web サイトに機能を追加しました。この演習では、次の方法を確認しました。

- GitHub Copilot Agent Mode で UI とデータレイヤーにまたがる新機能を実装する。
- Copilot Agent Mode でプロジェクトを調べ、関連ファイルを見つけ、複数のファイルを連携して変更する。
- コードベースにマージする前に、Copilot Agent Mode が生成した変更とテストをレビューする。

次は[Playwright MCP サーバーで機能をテストし][next-lesson]、プルリクエストを作成します。

### ボーナスの演習 — ページネーションを実装する

ゲーム一覧が増えるとページネーションが必要になります。この演習で学んだことを使い、Copilot にページネーションの実装を依頼してみましょう。次の点を検討してください。

- 既存の指示ファイルを使うなど、現在のベストプラクティスに従います。
- ページサイズをユーザーが選べるようにするか、固定にするかなど、ページネーションの方法を決めます。
- 希望する実装に必要なガイダンスを、プロンプトで Copilot に伝えます。
- Copilot に変更を依頼し、コンテキストを追加しながら反復する必要がある場合があります。Copilot と作業する際の通常の流れです。
