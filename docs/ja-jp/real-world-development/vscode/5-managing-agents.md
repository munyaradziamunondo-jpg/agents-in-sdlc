GitHub Copilot をエージェントモードで使うと、コードベースを調べ、変更を提案し、ファイルを編集し、コマンドを実行するなど、自律的に作業します。作業は開発者のマシンでリアルタイムに実行されます。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集を随時確認できます。差分をその場でレビューし、個々の変更を受け入れるか拒否するかを選び、エディターを離れずに追加プロンプトを送って作業を調整したり広げたりできます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して受け入れます。
- セッションの途中でエージェントに指示を送り、ハイコントラストに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントが、ハイコントラストモードを実装しています。作業中、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザーのために、ライトモードの切り替えも追加してほしいとのことです。新しい会話を最初から始めるのではなく、既存のセッションに指示を送り、作業範囲を広げます。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。ファイルの編集は差分と **Keep** / **Undo** の操作を含めてチャット内に表示されます。

1. 演習 4 の Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツールの操作を確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
    - 変更を受け入れるには **Keep** を選択します。
    - 変更を元に戻してエージェントにやり直させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開くと、セッション中にエージェントが変更したすべてのファイルを確認できます。

> [!NOTE]
> ターミナルコマンドの実行など、ツールの使用許可を求められた場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。最後に、変更内容の概要が表示されます。

## エージェントにライトモードを追加するよう依頼する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えも追加します。同じチャットセッションを続けるため、エージェントは先ほどの作業のコンテキストを保っています。変更したコンポーネント、スタイルの方針、設定を保存するローカルストレージの使い方も把握しています。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    よいできです。ハイコントラストの切り替えに加えて、ライトモードの切り替えも追加してください。ライトモードも同じ方法で実装し、設定をローカルストレージに保存して、同じユーザーインターフェイス (UI) 領域から使えるようにしてください。ハイコントラストとライトモードは、それぞれ独立して有効にできるようにしてください。
    ```

2. エージェントがすでに行った変更を確認し、ライトモードの追加を提案する様子を確認します。
3. ハイコントラストの作業と同じように、新しい編集をひとつずつレビューし、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの進め方が希望と異なる場合 (たとえば、切り替え UI を意図しない形でリファクタリングする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、補足プロンプトを送信します。

> [!TIP]
> 進行中のセッションに指示を送ると、最初からやり直すより早く作業を調整できます。追加プロンプトを使って、調整を依頼できます (「Cascading Style Sheets (CSS) を簡潔にして、セレクターの重複ではなく CSS 変数を使う」)、方向を修正できます (「3 つ目のトグルを追加せず、ライトモードを既存の設定パネルに組み込む」)、範囲を広げることもできます (「両方の切り替えにキーボードショートカットも追加する」)。

## 変更ファイルをレビューする

作業をコミットする前に、エージェントが変更したファイルをすべて簡単に確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが重視するアクセシビリティ (Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、ローカルストレージへの保存など) が反映されていることを確認します。
4. 内容に問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使い、進行中のセッションを監視して方向を調整しました。ファイルの編集を確認して受け入れるか拒否するかを選び、コンテキストを保ちながら追加プロンプトを送って作業範囲を広げました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を受け入れるか拒否しました。
- 追加プロンプトで進行中のセッションを調整しました。

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボを通じてローカルのカスタムエージェントが行った変更をレビューします。
