`quality-checks` スキルを使って自動チェックを実行し、Playwright MCP を使ってブラウザーでフィルタリング機能を確認しました。これらの機能を、明確な QA プロセスを持つカスタムエージェントにまとめます。

このレッスンでは、次のことを行います。

- カスタムエージェントが指示、スキル、MCP ツールと連携する方法を確認します。
- 再利用可能な品質保証プロファイルを作成して確認します。
- QA エージェントを選択し、フィルタリングの課題に照らして結果をレビューします。

## シナリオ

Tailspin Toys では、プルリクエスト (PR) を作成する前に、要件、コード品質、自動チェック、テストカバレッジ、ブラウザーでの動作を一貫してレビューしたいと考えています。カスタムエージェントを使うと、その QA プロセスを進め、再利用可能なレポートを作成できます。

## カスタムエージェントとは

カスタムエージェントは、Markdown プロファイルで定義する Copilot の専門的な役割です。プロファイルには、エージェントの目的、指示、利用できるツールを記述します。このワークショップでは、`.github/agents/qa.agent.md` に QA の役割を定義し、Copilot CLI で選択します。

これまでに使ったカスタマイズには、それぞれ異なる役割があります。リポジトリの指示はチームの標準を定めます。`quality-checks` スキルは繰り返し実行できるチェックをまとめます。Playwright MCP はブラウザーツールを提供します。QA プロファイルは、要件を評価して結果を報告するために、Copilot がこれらの機能をどう使うかを示します。これらを置き換えるものではなく、別の会話も必要ありません。

## QA プロファイルを作成する

機能の PR を開く前に、再利用可能な QA プロファイルを Copilot に作成させます。プロファイルでは、QA が実施するチェックと、その作業の制約を定義します。

1. Codespace に戻り、フィルタリングの会話が Interactive モードであることを確認します。
2. 既定のエージェントに、新しいカスタムエージェントを作成するよう依頼します。

   ```plaintext
   .github/agents/qa.agent.md に QA という名前のカスタムエージェントを作成してください。機能を課題と合意済みの要件に照らして確認し、リポジトリの指示に従い、quality-checks スキルを実行し、Playwright MCP で動作を検証し、テストカバレッジが不足している場合はテストを追加してください。

   各要件について、証拠とともに pass、fail、blocked のいずれかで報告させてください。実装コードを変更する前に確認を求め、変更をコミットしたりプルリクエストを開いたりしないでください。

   今はレビューできるようにプロファイルを作成するだけにしてください。
   ```

## プロファイルを確認する

新しいエージェントを使う前に、Copilot が意図した QA の流れと制約を取り込んだことを確認します。これにより、検証だけを依頼したのに、プロファイルが不完全だったり範囲が広すぎたりして、機能に変更が加わることを防げます。

1. `/diff` を入力し、`.github/agents/qa.agent.md` を開きます。
2. フロントマターを確認します。`description` は必須で、`name` は任意ですが、含めるとエージェントの表示名が分かりやすくなります。
3. プロファイルの指示を読み、QA が要件を確認し、リポジトリの指示に従い、`quality-checks` スキルを実行して、Playwright MCP を使うことを確認します。
4. QA が証拠とともに結果を報告し、実装コードを変更する前に確認を求め、変更をコミットしたり PR を開いたりしないことを確認します。
5. 責任範囲や制約が抜けている場合は、続行する前に既定のエージェントに修正を依頼します。

## 課題に対して QA を実行する

Copilot CLI は会話の開始時にプロジェクトのエージェントを読み込みます。プロファイルを作成した後、同じフィルタリングの会話を再開し、QA を選択すると、課題と計画の内容をそのまま利用できます。

1. 次のコマンドでエージェントを有効にします。

   ```plaintext
   /agent QA
   ```

> [!NOTE]
> 作成したばかりのエージェントは、利用可能なエージェントの一覧にまだ表示されない場合があります。上のコマンドで有効にできます。

2. 次のプロンプトで、QA エージェントに機能をレビューするよう依頼します。

   ```plaintext
   フィルタリング機能を課題と計画で決めた内容に照らしてレビューしてください。PR を作成できる状態ですか？
   ```

3. QA エージェントが作業を進める様子を確認します。
4. 作業が完了したら、レポートを読みます。
